# 0001 採用 Supabase 作為主要後端

日期：2026-10-22
狀態：已同意
關聯：BACKEND-01、PRODUCT-01

## 問題與選項

網站需要共用投稿、附件、審核與動態顯示，未來也需管理演出、曲目、人物、來源及校訂之間的關聯。比較 Firebase 與 Supabase；兩者均可透過 Google Drive API 歸檔，Drive 串接不限定後端平台。

## 決定與依據

使用者於本次對話明確指示「use supabase and write into memory」，同意採用 Supabase 作為主要後端。選擇依據是同時支援投稿互動及關聯資料管理。

規劃沿用 GitHub Pages 前端，以 Supabase Database、Auth、Storage 及後端程式承接資料、管理者身分、附件與審核流程；Google Drive 作為原始素材歸檔目的地。歸檔需另外實作授權、同步狀態、重試及避免重複建檔。

## 影響與驗收

本決策僅確認平台方向，尚未建立服務或串接。帳號歸屬、預算與付費方案、Drive 目的地及授權、審核與公開規則、附件限制及備份責任仍待確認；不代表授權建立付費服務、部署或變更權限。

先保留現有 content.json 與設計，優先實作新投稿，再依需求逐步導入音樂史資料。既有 IndexedDB 內容不得自動上傳。

正式收件需驗證跨裝置讀寫、待審內容與附件權限、核准後公開、Drive 歸檔及失敗重試，並分別驗證資料庫與附件備份還原。前端回退不能還原雲端資料。
