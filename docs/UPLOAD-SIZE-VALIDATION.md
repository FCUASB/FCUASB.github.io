# 附件超限提示與後台自動同步驗證紀錄

日期：2026-11-05。本機修改與驗證已完成，以 `codex/upload-size-validation` 分支交付審查，尚未合併或發布。起點為本機提交 `3e0315b`；驗證時透過 GitHub connector 確認遠端 main 為 `31c908d`。

## 問題與行為

雲端投稿模式原先跳過選檔時的大小限制，375.9 MB 影片仍會顯示「已準備好」。目前公開設定 `maxUploadBytes` 為 52,428,800 bytes（50 MiB，介面沿用 MB 標示）；現有後端會將超限附件標記 `FILE_TOO_LARGE`，投稿紀錄可能成立而附件未收到。

修正後，首頁會先檢查整批選取的附件；超限時在附件欄旁顯示檔名、上限及縮小檔案／改貼 YouTube 連結的提示，並將錯誤捲至可見範圍，保留先前準備好的附件。共享客戶端另在準備檔案及送出前檢查原檔大小，避免先建立收件紀錄。附件入口及旁邊的說明在開始填表時就顯示大小、數量限制與替代方式，並透過 `aria-describedby` 關聯至選檔欄；恰等於上限可接受。

後端仍會獨立檢查。若遠端限制比前端設定更嚴格，既有「文字已收到，部分附件未收到」處理仍保留。未更動既有失敗紀錄、雲端限制、權限或本機資料；未重新上傳任何既有內容。本機模式維持照片 25 MiB、影片 300 MiB 與最多 10 個檔案的原有規則。

## 後台自動同步

登入且分頁可見時，透過既有受驗證的 API 自動讀取目前分區：回憶投稿、既有回憶、音樂會或生平；開啟的歸檔狀態也會更新。每次讀取完成後等待 5 秒再執行下一次，切回分頁或視窗取得焦點時立即嘗試讀取，不需重新整理或為了更新資料重新登入。此機制是前端定期讀取，實際顯示時間仍受網路與 API 回應時間影響，並非後端即時推播。

請求不重疊；資料相同時保留原畫面節點。背景同步使用已套用的搜尋、篩選與目前頁次，不套用尚未送出的輸入。編輯對話框及手動操作進行中會暫緩同步，避免覆蓋草稿；完成後恢復。讀取途中才打開的編輯視窗同樣受到保護。同步失敗保留舊資料、標明最後成功時間並自動重試；登出、登入失效或離開頁面時停止讀取，過期回應不能還原私人畫面。

沿用 SDK 既有的 session 與自動更新 token 設定，每次 API 呼叫取得目前 session。不改動登入持久性、服務權限、資料庫、Realtime 設定或付費服務。訪客首頁仍沿用原先按需讀取；這次自動同步範圍為登入中的管理後台。

## 已驗證

- Node.js 24.18.0；`npm run test:cloud` 45 項、`npm run test:catalog` 19 項、`npm run test:home` 14 項通過（不同命令包含部分相同測試，不能合計為獨立案例數）。包含 50 MiB 邊界、超出 1 byte、375.9 MiB 影片、超限照片、附件保留、10 檔上限、送出前不建立收件紀錄及附件旁錯誤顯示。
- 後台測試涵蓋自動出現新投稿、附件 pending → ready、不重繪未變動資料、已更新 token 的沿用、搜尋草稿與目前頁次保留、隱藏／編輯暫緩、晚到回應、失敗重試及登出後不再讀取。
- `npm run build`、`npm run build:admin`、`npm run check`、`npm run check:admin` 與 `git diff --check` 通過。兩份首頁、後台及驗收頁與來源一致；既有 emoji／100 字、單一背景音樂、時間軸與資料完整性檢查通過。
- 以 HTTP 預覽及 Chrome 檢查 360／390／430px 與 1366px。附件超限表單、上限說明與後台未見水平溢出；附件錯誤與欄位的無障礙關聯正確，關閉按鈕正常。
- 隔離的本機預覽使用實際後台入口程式及合成 session／API 回應，實測新投稿與附件 ready／下載按鈕自動出現，未刷新或重新登入；編輯對話框保留草稿，取消後恢復同步。此證據不代表正式後端跨裝置驗收通過。
- 附件提示預覽以實際首頁建置檔執行 `fileRows`，傳入合成的 375.9 MiB 檔案中繼資料，確認錯誤位於附件旁並可在手機閱讀；不是透過作業系統選檔，也未實傳影片。
- 前一輪已檢查根目錄首頁的導覽，以及 `/handoff-v1.1/` 390px 相同提示與 Escape 關閉；原有肖像成功載入，原圖為 621 × 827。
