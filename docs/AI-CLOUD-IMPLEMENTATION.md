## AI 與帳號持有人分工

AI 可準備及審查資料模型、SQL、RLS、附件權限、收件 API、後台、歸檔工作、測試與交接文件。每階段先提交本機可審查成果，記錄部署與復原步驟。

校友團帳號持有人負責登入、連接器授權、首次指定管理員、Google OAuth 同意及秘密設定。不得將帳密、passkey、服務帳號私鑰、refresh token 或管理金鑰交給 AI 聊天或寫入 repository。Google Drive OAuth 與網站管理員登入為不同授權。

## 登入、角色與撤權

- 訪客繼續免登入投稿；不因後台支援 passkey 而提高投稿門檻。
- 每位管理員使用獨立帳號及穩定 user ID；角色綁定 ID，不綁裝置、passkey 或訪客填寫的 email。
- 依決策 0002 實作系統管理員、內容管理員、資料整理員；角色由受保護的後端資料維護。不得讓使用者自行修改 metadata 取得權限。
- 後端每次敏感操作核對有效成員及角色。停用或撤權後，即使舊 JWT 尚未到期也不能繼續讀取聯絡資料、匯出、編輯或產生附件連結；不能只等 token 更新。
- 聯絡資料與公開投稿分開存取；公開回應、搜尋、錯誤訊息與日誌均不含電話或 email。
- 記錄操作者 ID、操作時間、目標、前後變更及結果；匯出聯絡資料亦留紀錄，稽核不另複製秘密。

## Passkey 提案

官方文件目前將 passkey 標示為 experimental；採用前確認專案可用性並固定相容 SDK 版本，不以此作為唯一管理入口。

流程：受邀且已確認的管理員登入既有帳號後註冊個人 passkey；之後可用 passkey 或既有帳密登入同一帳號並取得相同角色。不得為同一人另造 passkey 專用帳號。

需先確定後台正式 HTTPS 網域、WebAuthn RP ID 與允許 origins，再註冊正式憑證。不得假設 GitHub Pages 路徑能隔離不同網站的 WebAuthn 身分，或換網域後舊憑證一定可用。

管理員可查看與移除自己的憑證，登記第二個可用憑證；新綁定、移除、角色變更及聯絡資料匯出建議要求近期重新驗證。Passkey 的生物辨識資料留在驗證器，不儲存在本站。

遺失裝置時以已確認的帳號復原流程處理；復原不得提升角色。必要時由其他系統管理員停用帳號及撤銷工作階段，再恢復授權。不允許以公開投稿聯絡資料作為管理員復原證明。首位管理員與最後一位管理員的保護及復原程序需於開放前完成。

參考：[Supabase Passkey authentication](https://supabase.com/docs/guides/auth/passkeys)。實際功能以串接時官方文件與專案設定為準。

## 分階段交付

1. 唯讀盤點現有 schema、Auth、Storage、Functions 與權限；不查閱非必要投稿個資，不覆蓋既有資料。
2. 在本機準備投稿、私人聯絡資料、附件、管理員角色、稽核及歸檔工作模型與權限；避免改動既有首頁設計。
3. 完成文字投稿及管理後台的最小流程；先驗證公開讀取、私人聯絡資料隔離、編輯及軟刪除，再接入大檔與歸檔。
4. 附件使用受控上傳與私有儲存；公開附件亦須受軟刪除控制，不使用永久公開 bucket 實現可撤回存取。短效連結仍可能在到期前有效，需明訂撤回時限或採每次驗權的媒體入口；已下載副本無法收回。
5. 以校友團 My Drive OAuth 設定背景歸檔、重試、防重複、授權失效告警；不要求訪客提供 Google 權限。
6. 確認正式網域及復原程序後，試行管理員 passkey；保留帳密入口。

## 驗收與待確認

程式檢查不能替代雲端權限測試。須分別證明訪客、各管理角色、已停用帳號及持有舊 token 的帳號能且只能執行允許操作，包含附件連結、直接 API、搜尋及匯出。角色變更、憑證移除與復原必須驗證。測試使用合成資料，不提交真實聯絡資料。

使用者目前要求先不執行壓測；200 人同時上傳仍只是目標。未完成實際驗收前，不宣稱正式收件、容量、跨裝置 passkey 或備份還原已通過。

待確認：後台正式網域、首位系統管理員與備援人員、復原信箱、passkey 試行同意、重新驗證規則、實際外部寫入及發布時機。不得因本計畫而自動建立付費資源或變更雲端權限。
