## 正式切換順序

1. 審查本分支差異；不得將歷史主工作區的其他草稿一起發布。
2. 在既有專案以交易執行 `supabase/deploy/existing-memories.sql`。此檔只擴充 catalog 類別與兩個既有 RPC，初始化 25 筆；不改投稿、聯絡資料或附件資料表，不授予新角色權限。重跑可保留雲端修改與下架狀態；不要重跑最初的 catalog-setup.sql。
3. 更新 catalog Edge Function 為本分支 `supabase/deploy/catalog.js`，沿用既有 JWT 設定及內部 Auth／角色檢查、CATALOG_ENABLED，不新增秘密或服務。
4. 唯讀核對 memory 總數／公開數與每筆來源內容、公開回應 managedMemoryIds，並確認未登入 POST 仍拒絕。既有音樂會與生平資料不可被初始化覆蓋。
5. 發布本分支的後台及兩份首頁（existingMemoriesEnabled=true），等待 CI／Pages 成功，再由已登入管理員核對四分區與跨瀏覽器同步。不得先發布啟用設定而跳過資料與 API。
6. 若回退前端，不回退或刪除已匯入的雲端紀錄；避免舊靜態首頁重新公開後台已下架的原文，應以關閉既有回憶顯示的版本回退。

目前尚未套用正式差異 SQL、更新遠端函式、推送、合併或發布。
